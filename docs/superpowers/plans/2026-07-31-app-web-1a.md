# App web (bloque 1A) — Plan de implementación

> **Para trabajadores agénticos:** SUB-SKILL REQUERIDA: usa `superpowers:subagent-driven-development` (recomendado) o `superpowers:executing-plans` para implementar este plan tarea por tarea. Los pasos usan sintaxis de casilla (`- [ ]`) para seguimiento.

**Goal:** Una app web local donde ves el calendario editorial del mes, descartas slots, editas sus textos, apruebas la grilla y editas el perfil de marca.

**Architecture:** Next.js App Router dentro del workspace. Los Server Components leen de `@gc/db` directamente; cuatro Server Actions escriben a través de `packages/operaciones`, el paquete nuevo al que se promueven las funciones que hoy viven en el CLI. Sin capa de API, sin estado de cliente para datos, sin trabajo largo.

**Tech Stack:** TypeScript 5 (ESM), Node 22+, pnpm workspaces, Next.js App Router, React, Tailwind, PostgreSQL 16, Drizzle ORM, Vitest.

**Spec:** [2026-07-31-app-web-1a-design.md](../specs/2026-07-31-app-web-1a-design.md)

## Global Constraints

- Node 22+; ESM (`"type": "module"`).
- Esquema y columnas en inglés `snake_case`; API de dominio, variables, comentarios y **todo texto visible en la interfaz** en español.
- **Un solo `.env`, en la raíz.** `next.config.ts` lo carga explícitamente; `apps/web` no tiene el suyo.
- **Ejecutar la suite completa con `pnpm test` desde la raíz**, nunca `pnpm -r test`.
- **La capa web nunca ejecuta trabajo largo ni llama al modelo.** Ninguna acción de este plan importa `@gc/ai`.
- **Estado inicial: 218 pruebas en verde, 7 paquetes, `pnpm -r typecheck` limpio.** Ninguna tarea puede terminar con menos.
- TDD estricto para la lógica: ninguna función de dominio o acción sin su prueba fallando primero.
- **El renderizado no se prueba** — no hay arnés de navegador y montarlo está fuera de alcance. Toda decisión de *qué* mostrar vive en funciones probadas; los componentes solo las consumen.
- Commits en español con prefijo convencional.

## Nota sobre el detalle de la interfaz

Este plan especifica de forma completa las **funciones de dominio, las acciones y los contratos de datos** — donde vive la corrección y donde están las pruebas. Para los componentes especifica la estructura, los datos que reciben y el comportamiento exigido, no cada clase de Tailwind. El estilo visual queda a criterio de quien implemente, siempre que cumpla lo que cada tarea describe.

- [ ] **Step 4: Implementar `datos.ts`**

```ts
import { crearConexion, esquema, type BaseDeDatos } from '@gc/db'
import { resolverOrganizacion } from '@gc/operaciones'
import { asc, eq } from 'drizzle-orm'

let cache: BaseDeDatos | undefined

/** Next.js reejecuta módulos entre peticiones en desarrollo; una conexión por
 *  petición agotaría el pool en minutos. */
export function conexion(): BaseDeDatos {
  if (!cache) {
    const url = process.env.DATABASE_URL
    if (!url) throw new Error('Falta DATABASE_URL')
    cache = crearConexion(url).db
  }
  return cache
}

export interface MarcaListada {
  id: string
  slug: string
  name: string
}

export async function marcasDeLaOrganizacion(
  db: BaseDeDatos,
  organizationId: string,
): Promise<MarcaListada[]> {
  return db
    .select({
      id: esquema.brands.id,
      slug: esquema.brands.slug,
      name: esquema.brands.name,
    })
    .from(esquema.brands)
    .where(eq(esquema.brands.organizationId, organizationId))
    .orderBy(asc(esquema.brands.createdAt))
}

export async function organizacionPorDefecto(db: BaseDeDatos): Promise<string> {
  return resolverOrganizacion(db)
}
```

export async function descartarSlot(

  organizationId: string,

        eq(esquema.planSlots.organizationId, organizationId),

}

`apps/web/src/acciones.ts` empieza con `'use server'`. Cada acción resuelve la organización, llama a la operación, revalida la ruta y traduce el error:

```ts
'use server'

import { clasificarError } from '@gc/shared'
import { revalidatePath } from 'next/cache'
import { conexion, organizacionPorDefecto } from './datos.js'
import { aprobarGrilla, descartarSlot, editarSlot } from '@gc/operaciones'

export type Resultado = { ok: true } | { ok: false; mensaje: string; reintentable: boolean }

async function ejecutar(
  ruta: string,
  fn: (db: Awaited<ReturnType<typeof conexion>>, organizationId: string) => Promise<void>,
): Promise<Resultado> {
  const db = conexion()
  try {
    await fn(db, await organizacionPorDefecto(db))
    revalidatePath(ruta)
    return { ok: true }
  } catch (error) {
    // Los mensajes del dominio ya están en español, ya nombran la marca por su
    // slug y ya explican el remedio: se muestran tal cual.
    return {
      ok: false,
      mensaje: error instanceof Error ? error.message : String(error),
      reintentable: clasificarError(error) === 'transitorio',
    }
  }
}
```

y las tres envolturas sobre `ejecutar`. `reintentable` es lo que decide si la interfaz ofrece un botón de reintentar.
